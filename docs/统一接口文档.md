# Interface Contract

本文件由成员 C 维护。其他成员如果需要改函数签名、数据结构、坐标系或主流程，先和 C 对齐，再改这里和 `src/common/`。

| 文件 / 目录 | 负责人 | 修改规则 |
|---|---|---|
| `main.py` | C | 只由 C 维护主流程、demo 和 interactive session |
| `src/common/` | C | 只由 C 维护共享类型和配置 |
| `src/interaction/` | A | A 负责，接口变化先通知 C |
| `src/simulation/` | B | B 负责，接口变化先通知 C |
| `src/planning/` | C | C 负责 |
| `src/control/` | D | D 负责，接口变化先通知 C |
| `src/visualization/` | D | D 负责 |
| `docs/member_todos/` | C 先建，个人可补充进度 | 不改接口定义 |

## Shared Types

共享类型在 `src/common/types.py`。

| 类型 | 作用 |
|---|---|
| `MoveCommand` | 用户输入后的统一命令，例如移动、reset、hand_on、obstacle_mode、quit |
| `Piece` | 一个棋子的 id、类型、颜色和所在格子 |
| `BoardState` | 当前棋盘上每个格子的棋子状态 |
| `ValidationResult` | 走法是否合法及原因 |
| `LogicalAction` | A 输出的逻辑动作，例如 pick/place |
| `MotionPrimitive` | C 输出的机器人运动基元，例如 approach/descend/lift；包含正在操作的 `piece_id` |
| `Obstacle` | 棋子、障碍柱、人手安全区等障碍物 |
| `SafetyDecision` | 人手/动态障碍介入后的响应：continue、safe 或 pause |
| `PrimitivePlanningContext` | 单个运动基元对应的动态障碍列表和安全决策 |
| `JointTrajectory` | D 可执行的关节轨迹和速度模式 |
| `RobotHandle` | B 返回的机器人 id、末端 id 和关节索引 |
| `SceneHandle` | B 返回的棋盘 id、棋子 id 映射和障碍物列表 |
| `OperationResult` | B attach/detach 等操作结果 |
| `ExecutionResult` | D 输出的执行结果和误差数据 |

## Cell And Coordinate Convention

- 棋盘列：`A` 到 `I`。
- 棋盘行：`1` 到 `10`。
- `A1` 是棋盘左下角的格点/落子点。
- 棋盘坐标到世界坐标只通过 `cell_to_world()` 转换。
- B 和 D 不单独定义坐标系。
- captured area 使用形如 `CAPTURED_BLACK_1` 的虚拟 cell。
- 棋盘格点参数来自 `Config`：`board_cols=9`、`board_rows=10`、`cell_size=0.04`。
- 棋子显示尺寸来自 `Config`：`piece_radius=0.015`、`piece_height=0.012`。

## Public Interfaces

### Main Session

| 函数 | 文件 | 输入 | 输出 | 当前行为 |
|---|---|---|---|---|
| `run_command(command, board, scene, robot, config)` | `main.py` | 一条 `MoveCommand` 和已有 session 状态 | dict | 不重建 session，执行一条命令并更新 `BoardState` |
| `run_demo(command_text="A1 B1")` | `main.py` | 一条文本命令 | dict | 一次性 demo，执行后退出 |
| `run_interactive(input_func=input, output_func=print, config=DEFAULT_CONFIG, max_steps=None)` | `main.py` | 输入函数、输出函数、配置 | dict | 长期会话：只初始化一次 board/robot/scene，循环轮询命令直到 `quit` |
| `apply_logical_actions(board, actions)` | `main.py` | 棋盘状态、A 输出的逻辑动作 | None | 在命令成功执行后更新内存中的棋盘状态 |

## End-To-End Pipeline

### One-Shot Demo

`python main.py --demo --command "A1 A2"` 当前流程：

1. A 解析一条文本命令。
2. B 加载 robot 和 scene。
3. A 创建棋盘、校验规则并生成 logical actions。
4. C 生成 motion primitives、逐 primitive 的 obstacle context、joint trajectory。
5. B 执行 attach/detach 占位。
6. D 执行 trajectory 并生成误差 summary。
7. 程序退出。

### Interactive Session

`python main.py --interactive` 当前流程：

1. 初始化一次 `BoardState`、robot、scene。
2. 循环调用 `poll_gui_command()` 获取一条用户命令。
3. 如果返回 `None`，继续等待；如果返回 `quit`，退出会话。
4. 对每条命令调用 `run_command()` 跑完整 A/B/C/D pipeline。
5. 命令成功后调用 `apply_logical_actions()` 更新内存棋盘状态。
6. 回到下一轮输入，不重建整个 session。

## Integration Rule

每个成员提交自己的模块前，至少保证：

```bash
python -m unittest discover -s tests -v
python main.py --demo
python main.py --demo --command "obstacle_mode 2"
```

如果改了函数签名，必须同步修改：

1. `src/common/types.py`
2. `docs/统一接口文档.md`
3. `tests/test_contract_interfaces.py`
4. 调用该接口的模块
